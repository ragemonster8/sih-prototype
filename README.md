# Charterwise

Charterwise is a front-end prototype for exploring dry-bulk coal chartering
decisions for India's East Coast. It connects a shipment scenario to an
illustrative freight outlook, port and vessel fit, voyage-cost comparisons, and
an explained recommendation.

The application is intentionally a deterministic demonstration. It does not
connect to a market-data feed, freight forecast, vessel database, or persistence
layer, and it must not be used as a live chartering or procurement decision tool.

## What it includes

- A shareable overview, dashboard, shipment-entry, and decision-report route.
- A shared, in-session shipment scenario used consistently across every page.
- Deterministic feasibility and voyage-cost calculations for three vessel classes
  and four East Coast destination ports.
- Separate, optional planning aids for schedule, landed-cost, and port-comparison
  views; these aids never alter the core recommendation.
- Responsive navigation, page metadata, accessible controls, and a root error
  boundary.

## Stack

- React 19 and TypeScript
- TanStack Start and TanStack Router
- Vite, Nitro, and Tailwind CSS
- TanStack Query, Recharts, Radix UI, and Lucide icons
- Bun for dependency management and scripts

## Getting started

Prerequisites: Bun 1.1+ and a current Node.js LTS release (Node 20+ recommended
for running the production output).

```bash
bun install
bun run dev
```

Open the URL Vite prints in the terminal (normally `http://localhost:3000`).

## Project structure

```text
src/
  components/       Shared layout, planning views, and UI primitives
  lib/              Scenario state and deterministic calculation modules
  routes/           TanStack file-based routes and route documentation
  test/             Test setup and route/calculation tests
  assets/           Local visual assets
  server.ts         SSR error-handling entry point
  start.ts          Shared TanStack Start middleware
```

`src/lib/scenario-context.tsx` owns the current in-session scenario.
`src/lib/chartering.ts` contains the core pure chartering calculation.
`src/lib/planning-aids.ts` and `src/lib/decision-insights.ts` contain
supplementary calculations only. Keeping these boundaries explicit ensures that
planning aids cannot silently change the core decision.

## Data and limitations

All rates, distances, vessel specifications, port constraints, waiting time,
market direction, and contract premiums are fixed illustrative assumptions.
Scenario changes remain in browser memory only and reset on refresh. Check the
in-product **Data & model assumptions** panel before interpreting any result.

## Development notes

- Route files use TanStack's file-based convention; see
  [`src/routes/README.md`](src/routes/README.md) before adding a route.
- `src/routeTree.gen.ts` is generated by TanStack Router. Do not hand-edit it.
- Keep the core model pure and scenario state shared so all routes present the
  same result for the same inputs.
- Do not rewrite published Git history.
